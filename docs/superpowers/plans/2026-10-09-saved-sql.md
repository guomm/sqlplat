# 个人 SQL 保存模块 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 用户持久保存个人 SQL，并从我的 SQL 列表重新打开、更新、另存为、重命名和删除。

**Architecture:** SQLAlchemy 模型与 Alembic 迁移存储个人查询。独立 FastAPI 路由模块复用现有登录与数据库依赖；前端列表独立组件，工作台标签绑定保存项 ID。

**Tech Stack:** Python 3.12、uv、FastAPI、SQLAlchemy、Alembic、MySQL、React、Ant Design、Monaco。

**Spec:** `docs/superpowers/specs/2026-10-09-saved-sql-design.md`

## Global Constraints

- 不使用 Docker、Celery 或 Redis。
- 每个用户只能访问自己的记录，管理员也不能跨用户访问。
- 名称去除首尾空白，1–100 字；SQL 最多 100 万字符，不允许空白内容，可保存未完成 SQL。
- 保存整份编辑器内容而非选区，连接可空；打开不执行、不加载结果。
- 保存项长期保留，与执行历史和临时结果清理分离。
- 当前目录未初始化 Git，不自动创建仓库或提交；交付以文件与运行验证为准。

## Review Focus

- 保存请求期间切换标签：返回时只绑定源标签。
- 他人随机 ID：读取、修改、删除都返回 404。
- 未选择或已禁用连接：允许保存，执行仍遵守连接校验。
- 保存项在其他页面被删除：更新返回明确提示，另存为才能新建。
- 超过 MySQL TEXT 长度的 SQL：LONGTEXT 实际持久化不截断。

# 个人 SQL 保存模块

## 目标

用户将工作台当前标签的全部 SQL 保存到平台数据库，长期保留供后续使用；仅保存 SQL 与连接上下文，不保存执行结果。每个用户只能访问自己的记录，管理员也不能跨用户访问。

## 页面与行为

- 工作台新增“保存 SQL”，初次保存弹窗填写名称（去除首尾空白，1–100 字），保存整份编辑器文本，忽略选区。
- 保存内容包括名称、SQL、可选连接 ID、数据库。未选择连接也允许保存；SQL 可未完成或暂时无法执行，保存不会验证或执行 SQL。
- 新导航“我的 SQL”：搜索名称或 SQL，按更新时间倒序分页；显示名称、SQL 摘要、连接/数据库、更新时间、打开/重命名/删除。
- 打开保存项，在新标签加载 SQL 和上下文，绑定保存项 ID，不加载结果、不执行。
- 已绑定标签“保存 SQL”更新原记录，另提供“另存为”创建新记录；保存弹窗显示原名称允许修改。不同记录允许同名。
- 删除前确认；若编辑标签绑定的记录已被删除，后续保存提示改用另存为，不自动新建或覆盖其他记录。
- 连接被禁用时仍可保存/打开，执行遵循原有连接启用校验；连接信息无法使用时，用户可重新选择连接。
- 保存时捕获当前标签和编辑器内容，返回后只更新对应标签绑定信息，避免用户切换标签造成串写。
- 浏览器草稿保留 savedSqlId，退出清除本地草稿但不删除数据库保存项。

## 数据与接口

新增 saved_queries 表，Alembic 迁移；字段：随机 ID、user_id、name VARCHAR(100)、sql LONGTEXT、可空 connection_id、database VARCHAR(128)、created_at/updated_at DATETIME(6)。按用户与更新时间建立索引。用户 ID 从登录会话取得，不接受客户端传入。

- GET /api/saved-queries：搜索 q、页码 page，返回本人的摘要列表与总数。
- POST /api/saved-queries：创建，返回 201 与完整记录。
- GET /api/saved-queries/{id}：读取本人完整记录。
- PUT /api/saved-queries/{id}：更新名称、SQL 和上下文。
- PATCH /api/saved-queries/{id}：仅更新名称，避免重命名覆盖其他浏览器刚更新的内容。
- DELETE /api/saved-queries/{id}：删除，返回 204。

所有接口要求登录；变更接口使用已有 CSRF 校验。未找到或他人记录统一 404。SQL 最多 100 万字符，不允许空白内容；连接 ID 不存在返回明确错误。保存内容不加入执行历史、线程池或结果清理周期。并发更新采用最后一次成功保存，不引入版本管理。

## 验证与交付

后端测试创建、搜索、分页、更新、删除、长度/空白校验、登录/CSRF/越权隔离。真实 MySQL 应用迁移并检查模型一致性，覆盖长 SQL 持久化。

浏览器验证从工作台保存，刷新/重新登录后查找与打开，编辑后更新、另存为、重命名和删除；确认打开不自动执行、不加载结果，保存整个标签而非选区。前端生产构建通过，检查按钮与列表实际布局。

保持本地 uv + Python 3.12、MySQL 运行方式，不使用 Docker、Celery 或 Redis。

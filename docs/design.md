# SQL 执行平台设计文档

更新日期：2026-10-09

## 1. 目标与范围

面向内部团队，开发支持 Doris 和 MySQL 的中文 SQL 执行平台。功能参考 Hue，界面采用现代工作台设计。

首版包含：

- 用户登录、退出、修改密码；管理员创建和禁用用户。
- 管理员配置、启用和禁用数据库连接，并测试连通性。
- 数据库、表和字段浏览。
- 多标签 SQL 编辑器：执行选中内容、光标所在完整语句或全部 SQL。
- 查询结果、执行状态、耗时、错误和写入影响行数展示。
- 个人执行历史，支持将历史 SQL 放回编辑器。
- Excel（XLSX）和 CSV 结果下载。

首版不包含定时任务、SQL 团队共享、查询审批、图表和其他数据源。

## 2. 技术架构

| 模块 | 方案 | 用途 |
| --- | --- | --- |
| 前端 | React、TypeScript、Vite、Ant Design | 中文工作台与管理页面 |
| SQL 编辑器 | Monaco Editor | 多标签编辑、选区及当前语句定位 |
| API | FastAPI | 登录、连接配置、元数据、执行任务和下载 |
| 数据库驱动 | PyMySQL | 连接目标 MySQL 和 Doris，按类型适配元数据查询 |
| 平台数据库 | MySQL | 保存用户、会话、连接配置、执行任务和历史 |
| 平台数据访问 | SQLAlchemy | 读写平台自身的数据，不接管目标数据库业务表 |
| 表结构升级 | Alembic | 管理平台数据库的表结构版本，不迁移目标业务数据 |
| SQL 后台执行 | 有并发上限的线程池 | 执行用户提交的 SQL，不提供定时调度 |
| 结果存储 | 本地持久卷 | 保存结果文件，供分页读取及导出 |
| 本地运行 | uv + Python 3.12、Node.js | 本地 API、前端开发服务与平台 MySQL |

首版不引入 Celery、Redis 或独立 Worker 服务。FastAPI API 进程内维护 SQL 执行线程池，使用 uv 管理 Python 3.12，默认运行单个 API 进程、单个实例。结果目录位于本地持久目录，服务重启后文件仍保留；不使用 Docker。

平台数据库与用户查询的目标数据库逻辑分离。目标数据库账号决定 SQL 的实际执行权限，平台支持查询、写入和 DDL。

## 3. 界面设计

采用浅色中文工作台，统一字体、间距、配色和状态反馈。

- 顶部：连接与数据库选择、用户菜单。
- 左侧：可搜索数据库和表，展开查看字段与类型。
- 中间：多标签 SQL 编辑器、三个执行按钮；编辑区与结果区高度可调整。
- 下方：结果集标签、表格、执行状态、耗时、影响行数和下载入口。
- 历史页面：个人执行记录筛选、详情及 SQL 回填。
- 管理页面：用户管理与数据库连接管理。

结果表格支持分页、列宽调整、复制单元格及横向滚动。编辑草稿保存在当前用户的浏览器本地，退出时清除，避免不同用户共用浏览器时泄露草稿。

## 4. 账号与连接

- 角色分为管理员、普通用户；管理员管理账号与连接，普通用户可使用启用的连接。
- 不开放公开注册，通过初始化命令创建首个管理员。
- 平台账号支持邮箱或自定义名称（中文、字母、数字、点、下划线、短横线），最长 80 位；创建与登录时去掉账号前后空格。邮箱仅作为登录账号，无邮件验证流程。
- 平台密码最少 8 位、最多 1024 位，新建用户、重置密码、修改密码和管理员初始化遵循同一规则。
- 使用 HttpOnly 会话 Cookie；密码使用安全哈希保存；变更接口校验 CSRF。
- 禁用用户后，其已有会话失效。
- 数据库密码加密保存，密钥从运行环境注入；密码不返回前端，不记录到日志。
- 用户只能访问自己的执行历史、任务及结果文件；管理员首版也不提供跨用户结果浏览功能。
- 连接配置包含名称、类型、主机、端口、数据库账号、密码、默认数据库和可选 TLS 配置。
- 连接禁用后拒绝新的执行请求，已运行任务继续完成。
- 管理员可删除连接，删除前弹窗确认；存在排队或运行任务时拒绝删除。采用逻辑删除保留历史关联，并清除地址、账号、密码及 TLS 凭据；删除后列表、测试、元数据、执行及编辑接口均不可使用该连接。历史和保存的 SQL 保留，再次打开时需重新选择连接。

## 5. SQL 执行流程

### 5.1 执行范围与语义

- 执行选中内容：仅提交用户选中的文本；无选区时禁用该按钮。
- 执行当前语句：提交光标所在的完整语句，可跨多行。
- 执行全部：提交当前编辑标签内的全部 SQL。
- 语句边界正确处理字符串和注释中的分号，不能直接按分号切分；前后端使用一致规则与共享测试样例。
- 一次任务内，多条语句按顺序使用同一目标数据库会话执行，支持 `USE` 等会话状态；不同任务使用独立连接。
- 默认自动提交，遇到错误停止后续语句，保留已完成语句的结果；已生效写入不自动回滚。
- 每条语句分别展示结果集或影响行数；首版不提供跨任务事务工作流。

### 5.2 线程池与任务生命周期

“后台执行”指用户点击执行后，SQL 在服务器线程中运行，而不是按时间自动触发。

1. API 校验用户、连接、SQL 和执行容量。
2. 将实际执行文本及上下文保存为任务，提交给执行线程池，立即返回任务 ID。
3. 工作线程使用独立的平台数据库会话和目标数据库连接，依次执行 SQL，并流式写入结果文件。
4. 工作线程更新状态及每条语句的执行信息；前端每 1 秒轮询一次，进入终态后停止轮询。
5. 用户刷新页面后，可以通过个人历史重新查看任务状态及结果。

默认同时运行最多 4 个任务，等待队列最多 20 个任务；两项均可通过环境变量配置。必须在提交前限制容量，不能依赖线程池默认的无界队列。容量不足返回 HTTP 429，页面提示稍后重试，不接受新的任务。

任务状态为：排队、运行、成功、失败、中断。连接失败或 SQL 明确报错记为失败；超时、连接断开导致执行结果无法确认时记为中断，并提示写入可能已生效。

默认任务执行超时为 300 秒，从开始运行时计时。使用目标数据库可用的查询超时及驱动网络超时；到期后停止后续语句并释放连接。不能仅将线程等待超时视为数据库 SQL 已停止。首版不提供主动取消按钮，也不承诺超时能回滚或立即终止数据库端操作。

失败、中断的 SQL 不自动重试。客户端不得自动重发执行请求，避免重复写入。

API 启动时，将上一次进程留下的排队和运行任务标记为中断，不重新执行。单进程、单实例部署是首版约束；如需多实例，应另行引入外部任务队列与共享任务调度。

## 6. 结果与导出

- 每个结果集在页面最多预览 1000 行，每个结果集最多保存 10 万行；预览支持分页。
- 使用流式游标读取结果并写入文件，不一次性加载全部数据到内存。
- 超过行数上限标记“结果已截断”；停止保存额外行，但完成当前结果协议处理后才能执行后续语句，不能因预览上限任意中断写入语句。
- 每个任务结果文件总量默认上限为 100 MB。达到上限时停止后续语句，关闭当前任务连接，保留完整落盘的部分结果并标明中断及截断；当前写入状态可能需核实。
- 结果按列位置保存，保留列名和类型信息，支持重复列名。
- 日期、NULL、二进制和数值使用明确的序列化规则；高精度数值和长整数不能经 JavaScript 浮点数转换丢失精度。
- 下载所选结果集的已保存数据，不重新执行 SQL；截断结果的下载入口明确提示不是完整查询结果。
- CSV 使用 UTF-8 BOM；XLSX 中长整数和高精度数值按文本导出，日期与空值正确处理。
- 将字符串按安全文本导出，避免单元格内容被 Excel 解释为公式。
- 默认结果文件保留 24 小时，执行历史保留 90 天，均可配置；结果过期后仍能查看保留期内的 SQL 和执行信息。
- 文件以不可猜测的内部标识保存，下载和分页请求先校验任务归属，不直接暴露文件目录。

API 生命周期内的轻量清理循环每小时清理一次过期数据，并在启动时清理；这属于存储维护，不是用户定时 SQL 功能，不需要 Celery 或 Redis。清理跳过运行中的任务，下载中的文件需在读取完成后再删除。

## 7. 数据与接口

平台实体：用户、登录会话、数据库连接、执行任务、语句执行记录及结果文件元数据。

执行历史保存用户、实际执行 SQL、连接标识及名称快照、选择的数据库、状态、开始与结束时间、耗时、错误、影响行数、结果保存行数及截断信息。历史不保存连接密码。

| 接口分组 | 功能 |
| --- | --- |
| `/api/auth` | 登录、退出、当前用户、修改密码 |
| `/api/users` | 管理员创建、修改、禁用用户 |
| `/api/connections` | 连接管理、测试连通性、查询库表字段 |
| `/api/executions` | 提交任务、状态、个人历史、结果分页、CSV/XLSX 下载 |

上表为后端内部路径。浏览器统一通过 `/sqlplat/` 访问平台，API 和下载使用 `/sqlplat/api/...`；Vite 与 Nginx 将其转发到后端 `/api/...`，并将会话 Cookie 的 Path 限定为 `/sqlplat/`。静态资源和编辑器 worker 由 Vite `base` 统一添加前缀。

提交任务返回 HTTP 202 和任务 ID。错误信息区分权限不足、连接失败、SQL 错误、容量不足、任务中断和结果过期；结果过期返回 HTTP 410。所有任务、结果与下载接口执行归属校验。

## 8. 实施顺序

1. 基础工程与登录：前后端结构、配置、迁移、部署、用户与会话管理。
2. 连接与元数据：配置、加密、测试连接、MySQL/Doris 库表和字段浏览。
3. 执行链路：语句边界、容量限制、线程池、任务状态、结果落盘及个人历史。
4. 工作台：多标签编辑、三种执行方式、轮询、结果表格、历史回填与本地草稿。
5. 导出与交付：Excel/CSV、过期清理、真实数据库联调、环境变量示例和部署文档。

## 9. 验收标准

- MySQL、Doris 均能执行查询、写入和 DDL，并正确显示错误及影响行数。
- 当前完整语句、选区和全文执行正确处理多行、字符串及注释中的分号。
- 多语句共享一次会话，遇错停止；已完成结果可查看，写入不自动重试。
- 登录失效、禁用账号、越权访问历史及下载正确拦截。
- 长查询不阻塞 API；并发和等待容量受控，满载返回明确提示。
- 重启后未完成任务标记中断，不重复执行；超时不错误宣称写入已回滚。
- 空结果、重复列名、中文、NULL、日期、长整数、高精度数值正确显示和导出。
- 10 万行及文件大小限制正确触发，截断提示清楚，导出与已保存结果一致。
- 过期结果无法下载，历史在其保留期内可查看。
- pytest 覆盖后端关键行为，前端组件测试覆盖执行范围，Playwright 验证登录、执行、历史及下载完整流程。

交付内容包括可运行代码、数据库迁移、管理员初始化命令、本地启动脚本、环境变量示例及启动文档。真实目标数据库凭据不写入源码。

## 10. 工作台体验补充（2026-10-09）

- SQL 格式化：有选区时仅格式化选区，否则格式化当前标签全文；两空格缩进、关键字大写，操作纳入编辑器撤销栈。MySQL 兼容格式化器不支持的语法提示失败并保留原文。
- 执行按钮说明：当前语句按光标位置定位完整语句；执行选中仅提交选区文本。
- 历史 SQL 列宽 360px、最多显示两行；“详情 / 打开”固定同一行，较窄屏幕可横向滚动查看。

## 11. 执行与历史交互调整（2026-10-09）

- 工作台仅提供一个“执行”按钮及相同语义快捷键：非空选区执行选中内容（全选即执行全文），无选区执行光标所在完整语句。
- 历史列表 SQL 占 50% 宽度，仅保留“打开”，移除详情抽屉。打开只回填 SQL、连接和数据库到新标签，不加载旧结果。
- 当前任务结果继续临时保存以支持预览及 CSV/XLSX 下载，按既定保留期清理；历史入口不展示结果。这一条取代此前历史详情及结果回填交互。

## 12. 个人 SQL 保存

新增“我的 SQL”导航与工作台“保存 SQL / 另存为”，保存项存入平台数据库、仅本人可见、长期保留。保存整份编辑器内容及连接上下文；打开只回填、不会执行。列表可搜索、重命名与删除。完整设计见 `docs/superpowers/specs/2026-10-09-saved-sql-design.md`。
